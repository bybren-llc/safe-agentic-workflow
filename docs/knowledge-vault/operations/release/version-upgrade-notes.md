# Version Upgrade Notes

A map to `docs/releases/`, which holds six files and no naming contract. Read this to find the
right document for the version you are upgrading from; read the documents themselves for the steps.

## The Six Documents

- [v2.5.0 Upgrade](../../../releases/v2.5.0-UPGRADE.md) — Skills 2.0 frontmatter across 18 skills,
  Agent Teams orchestration marked experimental, GitHub-Linear auto-sync.
- [v2.6.0 Structured Changelog](../../../releases/v2.6.0-STRUCTURED-CHANGELOG.md) — retroactively
  generated by `scripts/generate-changelog.sh`, then manually enriched.
- [v2.9.0 Upgrade](../../../releases/v2.9.0-UPGRADE.md) — Codex agents, shared skills, Cursor MCP,
  and the default branch moving to `main` with `dev` as the integration branch.
- [v2.9.0 Release Notes](../../../releases/v2.9.0-RELEASE-NOTES.md) — user-facing, same release.
- [v2.9.0 Structured Changelog](../../../releases/v2.9.0-STRUCTURED-CHANGELOG.md) — refs
  `v2.8.1..v2.9.0`, schema 1.0.0, 16 commits, dated 2026-03-18.
- [v2.10.0 Upgrade](../../../releases/v2.10.0-UPGRADE.md) — multi-domain sync and a
  manifest-driven engine that reaches beyond `.claude/`.

## Three Kinds, Inconsistently Applied

The `-UPGRADE`, `-RELEASE-NOTES` and `-STRUCTURED-CHANGELOG` suffixes mark three genres: operator
steps, user-facing narrative, and mechanical diff classification. Nothing requires a release to
produce all three — only v2.9.0 has the full set, and v2.10.0 ships an upgrade guide with no
structured changelog. Do not infer from a missing file that a release was minor.

## How This Relates To The Changelog Schema

`HARNESS_CHANGELOG.yml` has an `upgrade_doc` field pointing at `docs/releases/<ver>-UPGRADE.md`,
but it appears only inside a commented-out example, and the live `releases:` list is empty — so no
machine-readable entry links to any of these files. The directory listing above is the index. See
the [Harness Release Changelog Process](release-process.md) for why the schema stayed empty.

Open question: which version is current at this baseline is UNKNOWN — no `VERSION` file or
`package.json` version was found in scope, so the highest-numbered document is the only signal.
